# Demo runbook

## Current prototype demonstration

1. Serve `prototype/` on localhost as described in README.
2. Show topology and explicit disconnected runtime labels.
3. Create a deployment-scoped task with non-sensitive sample text.
4. Show it awaiting approval. Approve or reject; explain that this is only a browser-local record.
5. Run requested torque 12 Nm against maximum 10 Nm. Show BLOCKED, explicitly describing a scalar check.
6. Verify/export the local audit chain. Explain that SHA-256 links are not signatures or zkVM receipts.
7. Show the connection registry and state what remains unconnected.

Do not describe a failed interaction as passed. If crypto/storage is unavailable, show the blocker and complete G0 fixes before a live product demo.

## Target coding-track demo after G8 qualification

- 0:00–0:25: user submits a small fixture repository change; task ID and exact source revision appear.
- 0:25–0:55: show actual model ID, bounded inference request and worker isolation identity. No API keys on screen.
- 0:55–1:25: actual patch/test output and artifact hashes. A deliberately failing check blocks release.
- 1:25–1:55: show real receipt verification with pinned guest image and journal commitments. State the exact predicates proved and trusted runner assumptions.
- 1:55–2:25: operator approves the exact staging action; mutate the artifact in a separate negative-test fixture and show rejection.
- 2:25–3:00: successful staged artifact matches the approved digest; export evidence containing provenance and observed deployment result.

If proof generation is longer than the demo, run it beforehand and disclose generation time, job ID and source commit. Verify it live against the unchanged artifact. Never substitute a fabricated progress animation.

## Target personal and physical extensions

Personal AI: two workspaces and one expired task grant demonstrate denied retrieval, then an allowed grant retrieves a non-sensitive fixture with provenance.

Physical AI: show actual simulator output and fixed seed. Physical hardware must independently pass safety gate; only then show the validated policy, device acknowledgement, local interlock and emergency stop. A simulation-only demo is labeled simulation-only.

## Preflight and shutdown

Confirm account quota and budget cap, service health, tool allowlist, model catalog, device availability, proof verifier mode and recording privacy. After demo cancel jobs, revoke temporary grants, disable edge release, remove test data under retention policy, and reconcile actual compute usage. Never leave GPU resources running unintentionally.
